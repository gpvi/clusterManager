# 配置与运行

## 1. 静态配置文件

主配置文件是 [config/conf.yaml](../cluster/config/conf.yaml)。

```yaml
backend: "k8s"                 # 默认后端
db_path: ""                    # SQLite 路径（空则自动 runtime/cluster.db）
containerd_socket: ""          # containerd socket（空则自动检测）

paths:
  redis_host_config_path: "setup/redis/config"
  redis_config_path: "/data/redis/config"
  redis_host_data_path: "setup/redis/data"
  redis_config_data_path: "/data/redis/data"
  runtime_state_dir: "runtime"

kubernetes:
  kube_config_path: ""
  namespace: "default"
  base_node_port: 30000

configs:
  save_file_name: "run_time_config.yaml"
  image_name: "redis:7-alpine"
  redis_port: 6379

cache:
  enabled: false               # Enable cache subsystem
  max_bytes: 1073741824        # Max cache size per node (1GB)
  ttl: 3600                    # Default TTL in seconds
  hot_key_threshold: 100       # Requests per 10s window to mark as hot
  hot_replicas: 2              # Extra replicas for hot keys
  db_rate_limit: 200           # DB queries per second
  server_ip: "0.0.0.0"         # gRPC bind address
  server_port: 8001            # gRPC cache port
  gossip_port: 9001            # Memberlist gossip port
  api_gateway: false           # Enable HTTP API gateway on :9999
  cache_group_name: "default"  # Cache namespace
  seeds: []                    # Seed node addresses
  tls_mode: "insecure"         # TLS: insecure | server | mutual
  tls_cert_file: ""
  tls_key_file: ""
  tls_ca_file: ""

dns:
  enabled: false
  domain: "svc.cluster.local"
  naming_template: "{{.ClusterName}}-redis-{{.Index}}.{{.ClusterName}}-svc.{{.Namespace}}"
```

## 2. 配置项说明

### 顶层

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `backend` | 默认后端：`k8s` / `podman` / `containerd` | `k8s` |
| `db_path` | SQLite 数据库路径，空则使用 `runtime/cluster.db` | `""` |
| `containerd_socket` | containerd socket 路径 | 自动检测（Linux: `/run/containerd/containerd.sock`, Windows: `\\.\pipe\containerd-containerd`） |

### paths

| 配置项 | 说明 |
|--------|------|
| `redis_host_config_path` | 宿主机上的 Redis 配置目录 |
| `redis_config_path` | 容器内 Redis 配置挂载路径 |
| `redis_host_data_path` | 宿主机 Redis 数据目录 |
| `redis_config_data_path` | 容器内 Redis 数据挂载路径 |
| `runtime_state_dir` | 运行时状态文件根目录 |

### kubernetes（仅 K8s 后端）

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `kube_config_path` | kubeconfig 路径 | `$KUBECONFIG` → `~/.kube/config` → InCluster |
| `namespace` | K8s namespace | `default` |
| `base_node_port` | NodePort 起始端口 | `30000` |

### configs

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `save_file_name` | 运行时配置文件名 | `run_time_config.yaml` |
| `image_name` | Redis 镜像 | `redis:7-alpine` |
| `redis_port` | Redis 容器端口 | `6379` |

### cache

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `enabled` | 是否启用缓存子系统 | `false` |
| `max_bytes` | 单节点最大缓存字节数 | `1073741824`（1GB） |
| `ttl` | 缓存默认 TTL（秒） | `3600` |
| `hot_key_threshold` | 10 秒窗口内标记为热 key 的请求次数阈值 | `100` |
| `hot_replicas` | 热 key 额外副本数 | `2` |
| `db_rate_limit` | 数据库查询限速（QPS） | `200` |
| `server_ip` | gRPC 绑定地址 | `0.0.0.0` |
| `server_port` | gRPC 缓存服务端口 | `8001` |
| `gossip_port` | Memberlist 节点发现端口 | `9001` |
| `api_gateway` | 是否启用 HTTP API 网关（:9999） | `false` |
| `cache_group_name` | 缓存分组名称 | `"default"` |
| `seeds` | 种子节点地址列表 | `[]` |
| `tls_mode` | TLS 模式：`insecure` / `server` / `mutual` | `"insecure"` |
| `tls_cert_file` | TLS 证书文件路径 | `""` |
| `tls_key_file` | TLS 私钥文件路径 | `""` |
| `tls_ca_file` | TLS CA 证书文件路径 | `""` |

### dns

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `enabled` | 是否启用 DNS 自动发现 | `false` |
| `domain` | DNS 域名后缀 | `"svc.cluster.local"` |
| `naming_template` | 节点命名模板（Go template） | `"{{.ClusterName}}-redis-{{.Index}}.{{.ClusterName}}-svc.{{.Namespace}}"` |

## 4. 运行时状态

### 文件结构

```
<runtime_state_dir>/
├── cluster.db                      # SQLite 数据库（持久化状态与审计日志）
└── <clusterName>/
    └── run_time_config.yaml        # 集群配置快照
```

### SQLite 表结构

- **clusters** — 集群元数据（名称、后端、shard 数、状态、时间戳）
- **containers** — 容器实例（名称、ID、IP/端口、角色、状态）
- **operations** — 操作审计日志（操作类型、详情、成功/失败、时间戳）

## 5. 前置条件

| 后端 | 前置条件 |
|------|----------|
| Podman | `podman` CLI 可用，`podman machine` 运行中（Windows） |
| Kubernetes | 可访问的 K8s 集群，`kubectl` / kubeconfig 可用 |
| Containerd | containerd 服务运行中，socket 可访问，编译时加 `-tags containerd` |

所有后端均需：`redis.conf` 放置在 `paths.redis_host_config_path` 下。

## 6. Cache 节点启动

缓存节点是独立于 Redis 集群的分布式缓存层，无需 Redis 即可直接启动。

### 基础启动

```bash
# 独立模式（无种子节点）
./cluster cache --port=8001 --gossip=9001
```

### 集群模式（带 API 网关和种子节点）

```bash
./cluster cache --port=8002 --gossip=9002 --api --seeds=10.0.1.1:8001
```

### CLI 参数说明

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `--port` | gRPC 缓存服务端口 | 配置文件 `cache.server_port` |
| `--gossip` | Memberlist 节点发现端口 | 配置文件 `cache.gossip_port` |
| `--api` | 启用 HTTP API 网关 | 配置文件 `cache.api_gateway` |
| `--seeds` | 种子节点地址列表（逗号分隔） | 配置文件 `cache.seeds` |

## 7. Cache 架构设计

缓存子系统采用三层架构（L1 / L2 / L3），逐级回退：

```
┌─────────────┐
│  L1: GeeCache (内存)   │  响应时间 ~1μs
│  单节点 LRU 缓存       │
└──────┬──────┘
       │ miss
┌──────v──────┐
│  L2: Redis Cluster      │  响应时间 ~0.5ms
│  分布式缓存             │
└──────┬──────┘
       │ miss
┌──────v──────┐
│  L3: Getter 回调        │  响应时间 不定
│  数据库 / 外部 API      │
└─────────────┘
```

| 层级 | 实现 | 延迟 | 说明 |
|------|------|------|------|
| L1 | GeeCache 内存 LRU | ~1μs | 单节点本地缓存，基于 LRU 淘汰策略 |
| L2 | Redis Cluster | ~0.5ms | 分布式缓存层，通过 Redis 集群共享 |
| L3 | Getter 回调 | 不定 | 回源到数据库或外部 API，由用户自定义回调函数 |

### 关键特性

- **一致性哈希**：节点增删仅影响少量 key 的映射
- **节点发现**：通过 Memberlist（SWIM 协议）自动发现和健康检查
- **热 key 感知**：统计 10 秒窗口内的请求频率，自动为热 key 创建额外副本
- **TLS 支持**：支持 `insecure` / `server` / `mutual` 三种 TLS 模式
- **缓存分组**：通过 `cache_group_name` 隔离不同的缓存命名空间
