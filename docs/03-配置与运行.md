# 配置与运行

## 1. 静态配置文件

主配置文件是 [config/conf.yaml](/e:/Projects/clusterManager/clusterManager-main/config/conf.yaml)。

当前默认内容：

```yaml
paths:
  redis_host_config_path: "setup/redis/config"
  redis_config_path: "/data/redis/config"
  redis_host_data_path: "setup/redis/data"
  redis_config_data_path: "/data/redis/data"
  runtime_state_dir: "runtime"

podman:
  endpoint: "npipe://\\\\.\\pipe\\podman-machine-default"
  network_name: "podman"

configs:
  save_file_name: "run_time_config.yaml"
  container_info_file_name: "containers.json"
  image_name: "myredis"
  redis_port: 6379
```

## 2. 配置项含义

### `paths.redis_host_config_path`

- 宿主机上的 Redis 配置目录
- 会被 bind mount 到容器内

### `paths.redis_config_path`

- 容器内 Redis 配置目录
- 启动命令里会拼出 `redis.conf` 路径

### `paths.redis_host_data_path`

- 宿主机上的 Redis 数据目录

### `paths.redis_config_data_path`

- 容器内数据目录

### `configs.save_file_name`

- 运行时配置保存文件名
- 当前默认值是 `run_time_config.yaml`

### `configs.container_info_file_name`

- 容器快照文件名
- 当前默认值是 `containers.json`

### `configs.image_name`

- 创建 Podman 容器时使用的镜像名

### `configs.redis_port`

- Redis 容器默认服务端口
- 未显式传命令行参数时，可由配置文件提供默认值

### `podman.endpoint`

- Podman API 连接地址
- 现在已经从源码中提取出来，可按平台或环境改配置

### `podman.network_name`

- 容器网络名
- 读取容器 IP 时会优先使用这个网络名

### `paths.runtime_state_dir`

- 运行时状态目录
- `run_time_config.yaml` 和 `containers.json` 会保存到这里

## 3. 环境变量覆盖

`model/config.go` 支持用环境变量覆盖配置：

- `REDIS_HOST_CONFIG_PATH`
- `REDIS_CONFIG_PATH`
- `REDIS_HOST_DATA_PATH`
- `REDIS_CONFIG_DATA_PATH`
- `CLUSTER_SAVE_FILE_NAME`
- `CLUSTER_CONTAINER_INFO_FILE`
- `CLUSTER_IMAGE_NAME`
- `CLUSTER_STATE_DIR`
- `PODMAN_ENDPOINT`
- `PODMAN_NETWORK_NAME`
- `CLUSTER_REDIS_PORT`

这部分是项目里比较实用的一点，说明代码已经考虑过“默认配置 + 临时覆盖”的使用方式。

## 4. 运行时文件

### `run_time_config.yaml`

创建成功后写入，当前保存：

- `nodes_per_shard`
- `port`

用途：

- 给扩容操作恢复必要上下文
- 按集群保存到 `runtime/<clusterName>/run_time_config.yaml`

### `containers.json`

创建成功后写入，保存容器信息快照：

- host ip / host port
- container ip / container port
- 容器 id / name
- 按集群保存到 `runtime/<clusterName>/containers.json`

## 5. 运行依赖

项目真实依赖不仅是 Go 依赖，还包括：

- Podman 可用
- Redis 镜像可用
- Redis 配置目录存在
- Podman API socket 可连接

你当前提供的 Podman endpoint 是：

```text
npipe://\\.\pipe\podman-machine-default
```

这说明：

- 项目已经把 Podman endpoint 提取到配置层
- 当前仓库默认配置已经按你的 Windows endpoint 进行设置
- 如果切换到其他平台，只需要改配置或环境变量，不必再改源码

## 6. 实际运行步骤建议

如果只是回顾项目，建议按这个顺序理解：

1. 确认镜像名和 Redis 配置路径
2. 确认 Podman endpoint 是否与源码一致
3. 先执行 `create`
4. 再执行 `scale`
5. 最后执行 `delete`

如果后续要重新启用这个项目，最先应该改的是：

1. Podman 连接地址改为可配置
2. 补齐 `setup/redis/data`
3. 统一 `README`、安装文档和源码里的运行文件名

## 7. 目前仍值得继续抽离的配置

这部分已经比之前好很多，真正还适合继续抽离的，主要是策略型配置：

- Redis cluster bus port 计算规则
- 容器命名规则
- 创建前环境自检规则

当前跨平台和关键运行参数本身已经进入配置层，但更细的运行策略还在代码里。
