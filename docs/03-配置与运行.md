# 配置与运行

## 1. 静态配置文件

主配置文件是 [config/conf.yaml](/e:/Projects/clusterManager/clusterManager-main/config/conf.yaml)。

当前默认内容：

```yaml
paths:
  redis_host_config_path: "setup/redis/config"
  redis_config_path: "/data/redis/config"
  redis_host_data_path: "setup/redis/data"
  redis_config_data_path: "/data/redis/data"
  runtime_state_dir: "runtime"

podman:
  endpoint: ""
  network_name: "podman"

configs:
  save_file_name: "run_time_config.yaml"
  container_info_file_name: "containers.json"
  image_name: "myredis"
  redis_port: 6379
```

## 2. 配置项含义

### `paths.redis_host_config_path`

- 宿主机上的 Redis 配置目录
- 会被 bind mount 到容器内

### `paths.redis_config_path`

- 容器内 Redis 配置目录
- 启动命令里会拼出 `redis.conf` 路径

### `paths.redis_host_data_path`

- 宿主机上的 Redis 数据目录

### `paths.redis_config_data_path`

- 容器内数据目录

### `configs.save_file_name`

- 运行时配置保存文件名
- 当前默认值是 `run_time_config.yaml`

### `configs.container_info_file_name`

- 容器快照文件名
- 当前默认值是 `containers.json`

### `configs.image_name`

- 创建 Podman 容器时使用的镜像名

### `configs.redis_port`

- Redis 容器默认服务端口
- 未显式传命令行参数时，可由配置文件提供默认值

### `podman.endpoint`

- Podman API 连接地址
- 现在已经从源码中提取出来，可按平台或环境改配置
- 若为空，代码会优先尝试从 `podman system connection list --format json` 中读取默认连接

### `podman.network_name`

- 容器网络名
- 读取容器 IP 时会优先使用这个网络名

### `paths.runtime_state_dir`

- 运行时状态目录
- `run_time_config.yaml` 和 `containers.json` 会保存到这里

## 3. 环境变量覆盖

`model/config.go` 支持用环境变量覆盖配置：

- `REDIS_HOST_CONFIG_PATH`
- `REDIS_CONFIG_PATH`
- `REDIS_HOST_DATA_PATH`
- `REDIS_CONFIG_DATA_PATH`
- `CLUSTER_SAVE_FILE_NAME`
- `CLUSTER_CONTAINER_INFO_FILE`
- `CLUSTER_IMAGE_NAME`
- `CLUSTER_STATE_DIR`
- `PODMAN_ENDPOINT`
- `PODMAN_NETWORK_NAME`
- `CLUSTER_REDIS_PORT`

额外说明：

- `REDIS_HOST_CONFIG_PATH` 和 `REDIS_HOST_DATA_PATH` 现在支持 `/mnt/...` 这种 Linux 风格绝对路径
- 这对“Windows 客户端 + Podman machine / WSL 服务端”场景很关键

这部分是项目里比较实用的一点，说明代码已经考虑过“默认配置 + 临时覆盖”的使用方式。

## 4. 运行时文件

### `run_time_config.yaml`

创建成功后写入，当前保存：

- `nodes_per_shard`
- `port`

用途：

- 给扩容操作恢复必要上下文
- 按集群保存到 `runtime/<clusterName>/run_time_config.yaml`

### `containers.json`

创建成功后写入，保存容器信息快照：

- host ip / host port
- container ip / container port
- 容器 id / name
- 按集群保存到 `runtime/<clusterName>/containers.json`

## 5. 运行依赖

项目真实依赖不仅是 Go 依赖，还包括：

- Podman 可用
- Redis 镜像可用
- Redis 配置目录存在
- Podman API socket 可连接

当前项目已经实机验证通过的连接形态是：

```text
ssh://user@127.0.0.1:9280/run/user/1000/podman/podman.sock
```

这说明：

- 项目已经把 Podman endpoint 提取到配置层
- 当前代码已支持读取 Podman 默认 connection 的 `URI`、`Identity` 和 machine 信息
- 对 Windows + Podman machine，不再依赖硬编码 `npipe://...`

## 6. 实际运行步骤建议

如果只是回顾项目，建议按这个顺序理解：

1. 确认镜像名和 Redis 配置路径
2. 确认 Podman machine 已启动且 `podman system connection list` 返回默认 connection
3. 先执行 `create`
4. 再执行 `scale`
5. 最后执行 `delete`

如果后续要重新启用这个项目，最先应该改的是：

1. 明确区分“本地运行时目录”和“远端 Podman machine 可见挂载路径”
2. 补齐 `setup/redis/data`
3. 继续收敛创建 / 扩容链路中的等待与重试策略
