# 架构与目录

## 1. 目录结构

项目当前可以概括为下面几层：

```text
clusterManager-main/
├─ cmd/              CLI 命令定义
├─ config/           静态配置
├─ model/            核心业务逻辑
├─ setup/            Redis 配置和镜像相关文件
├─ utils/            工具函数
├─ img/              README / DESIGN 配图
├─ main.go           程序入口
├─ README.md         使用说明
├─ DESIGN.md         设计草稿
└─ INSTALLATION_GUIDE.md  安装说明
```

## 2. 分层职责

### `main.go`

- 只做一件事：执行 Cobra 根命令

### `cmd/`

负责解析用户输入并调用 `model` 层：

- `root.go`：根命令与帮助信息
- `create.go`：读取参数并执行创建
- `delete.go`：读取集群名并执行删除
- `scale.go`：读取集群名和新增 shard 数并执行扩容

这一层几乎不包含业务逻辑，主要是入口和参数传递。

### `model/`

这是项目的核心层，主要包含 4 组职责：

1. 配置读取
2. 容器编排
3. Redis Cluster 拓扑管理
4. 高层动作封装

对应主要文件：

- `config.go`：读取 `config/conf.yaml`，并写入全局配置变量
- `containers_manger.go`：管理 Podman 容器与 `ContainerNode`
- `cluster_node.go`：定义 Redis Cluster 节点数据结构
- `cluster_manager.go`：管理节点发现、主从关系、slot 分配、slot 迁移
- `create_cluster.go`：封装“创建集群”动作
- `scale_cluster.go`：封装“扩容集群”动作
- `delete_cluster.go`：封装“删除集群”动作

### `utils/`

提供基础能力：

- IP/端口解析
- Redis `Do` 命令包装
- YAML 读写
- 文件存在判断

## 3. 核心对象关系

### `ContainerNode`

表示一个 Redis 容器实例，主要关心：

- 容器 ID / 名称
- 宿主机映射端口
- 容器内 IP
- 所属集群名

它解决的是“容器怎么连”的问题。

### `ClusterNode`

表示 Redis Cluster 里的逻辑节点，主要关心：

- 节点 ID
- IP / port
- master / slave 身份
- master 归属
- slot 范围

它解决的是“集群拓扑是什么”的问题。

### `ContainersManager`

负责管理一组容器：

- 创建容器
- 拉取当前容器信息
- 建立 `IP -> Node`、`ID -> Node` 索引
- 序列化保存容器信息

### `ClusterManager`

负责管理一组 Redis Cluster 节点：

- 创建集群基础资源
- 执行 `CLUSTER MEET`
- 设置主从关系
- 分配 slot
- 扩容时迁移 slot
- 查询并解析 `CLUSTER NODES`

## 4. 实际调用链

创建集群时的主调用链：

```text
main.go
  -> cmd/create.go
    -> model.CreatePodmanConnection()
    -> model.CreateClusterAction()
      -> InitConfig()
      -> NewClusterManager()
      -> ContainersManager.GetCurContainersNum()
      -> ClusterManager.CreateCluster()
      -> ClusterManager.SetAllNodeRole()
      -> ClusterManager.AllocateSlots()
```

扩容时的主调用链：

```text
cmd/scale.go
  -> model.ScaleClusterAction()
    -> InitConfig()
    -> 读取 run_time_config.yaml
    -> ContainersManager.UpdateAllContainersInfo()
    -> UpdateAfterMeet()
    -> UpdateAfterSetNodeRole()
    -> UpdateSlots()
    -> AddShaders()
    -> MigratesSlotsToEmptyNode()
```

## 5. 当前架构特点

这个架构的优点：

- CLI、容器、集群逻辑有基本分层
- Redis Cluster 的核心行为都集中在 `ClusterManager`
- 可以顺着动作入口快速追踪执行路径

当前的明显限制：

- 配置依赖全局变量，耦合较重
- Podman 连接地址写死，不利于跨平台
- “容器模型”和“Redis 集群模型”混在一个管理器里，后续扩展会变复杂
- 仍有少量历史命名包袱，例如 `containers_manger.go`
