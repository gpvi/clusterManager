# 故障排查

## 1. Podman 连接失败

常见现象：

```text
create podman conection fail
```

检查：

```powershell
podman machine list
podman machine start
podman system connection list
```

处理建议：

- 如果 `config/conf.yaml` 中 `podman.endpoint` 为空，项目会尝试读取 Podman 默认 connection。
- 如果默认 connection 不正确，显式设置 `PODMAN_ENDPOINT` 或 `CONTAINER_HOST`。
- Windows + Podman machine 场景下，默认连接通常是 `ssh://.../podman.sock`。

示例：

```powershell
$env:PODMAN_ENDPOINT="ssh://user@127.0.0.1:9280/run/user/1000/podman/podman.sock"
```

## 2. 镜像不存在

常见现象：

```text
no such image: myredis
```

处理：

```bash
./scripts/build-image.sh
```

或：

```bash
podman build -t myredis -f ./setup/redisv3.dockerfile .
```

如果你改了镜像名，需要同步修改：

- `config/conf.yaml` 的 `configs.image_name`
- 或环境变量 `CLUSTER_IMAGE_NAME`

## 3. bind mount 路径不可见

常见现象：

- 容器创建失败
- Redis 启动后找不到 `redis.conf`
- Windows 本地路径在 Podman machine 中不可访问

关键点：

Go 程序运行的机器和 Podman service 看到的文件系统可能不是同一个。Windows + Podman machine 场景下，容器挂载路径要使用 Podman machine 内可见的 Linux 路径。

示例：

```powershell
$env:REDIS_HOST_CONFIG_PATH="/mnt/e/Projects/clusterManager/clusterManager-main/setup/redis/config"
$env:REDIS_HOST_DATA_PATH="/mnt/e/Projects/clusterManager/clusterManager-main/setup/redis/data"
```

确认路径：

```powershell
podman machine ssh
ls /mnt/e/Projects/clusterManager/clusterManager-main/setup/redis/config
```

## 4. Redis 节点无法互相发现

常见现象：

```text
ClusterManager not fully synchronized, retrying...
cluster did not synchronize within the expected time
```

检查：

```powershell
podman ps --filter label=clusterName=<clusterName>
podman inspect <container-id>
```

关注项：

- 容器是否都在运行
- 容器是否在配置的 `podman.network_name` 网络上
- `redis.conf` 是否开启 cluster
- 容器内 Redis port 是否和 `RedisContainerPort` 一致

## 5. 创建失败后有残留容器

创建流程在失败后会尝试按 `clusterName` 自动回滚容器。若回滚未成功，可以手动查看：

```powershell
podman ps -a --filter label=clusterName=<clusterName>
```

删除：

```powershell
./cluster delete -n <clusterName>
```

如果 CLI 无法删除，再使用 Podman 手动删除对应容器。

## 6. 扩容找不到运行时配置

常见现象：

```text
error reading from JSON file
```

虽然错误文字里还保留了 `JSON`，实际读取的是：

```text
runtime/<clusterName>/run_time_config.yaml
```

处理：

- 确认集群名是否正确
- 确认 `CLUSTER_STATE_DIR` 或 `paths.runtime_state_dir` 是否变更过
- 如果运行时文件丢失，建议先删除残留容器，再重新创建集群

## 7. 端口连接失败

项目创建容器时会让 Podman 随机映射宿主机端口。不要假设宿主机端口一定是 `6379`。

查看映射：

```powershell
podman ps --filter label=clusterName=<clusterName>
```

或读取：

```text
runtime/<clusterName>/containers.json
```

然后使用映射出的 host port：

```powershell
redis-cli -p <host-port> ping
redis-cli -p <host-port> cluster nodes
```

## 8. 常见清理步骤

删除指定集群：

```powershell
./cluster delete -n <clusterName>
```

确认容器是否清空：

```powershell
podman ps -a --filter label=clusterName=<clusterName>
```

确认运行时目录：

```powershell
Get-ChildItem runtime
```

如果 `runtime/<clusterName>` 仍存在但为空，可以手动删除；如果里面还有文件，先确认不是其他进程正在使用。
