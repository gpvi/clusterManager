# 故障排查

## 1. K8s 连接失败

常见现象：

```text
create k8s clientset fail
neither kubeconfig found nor in-cluster config available
```

检查：

- `$KUBECONFIG` 环境变量是否指向有效的 kubeconfig
- `~/.kube/config` 是否存在
- 如果在集群内运行，Pod 是否配置了 ServiceAccount

处理建议：

- 显式设置 `kubernetes.kube_config_path` 在 `config/conf.yaml`
- 或设置 `KUBECONFIG` 环境变量
- 使用 `kubectl cluster-info` 验证集群可访问性

## 2. Pod 创建失败

常见现象：

```text
failed to create pod <name>
```

检查：

```powershell
kubectl get pods -n <namespace> -l managed-by=clusterManager
kubectl describe pod <pod-name> -n <namespace>
```

常见原因：

- 镜像 `myredis` 不存在或拉取失败
- Namespace 不存在
- 资源配额不足

处理建议：

- 确保 Redis 镜像已构建或可从 registry 拉取
- 检查 `configs.image_name` 配置
- 使用 `kubectl get events -n <namespace>` 查看具体错误

## 3. Pod 一直不进入 Running 状态

常见现象：

```text
Waiting for pod <name> (phase=Pending)...
timed out waiting for pod <name> to become ready
```

Pod 等待超时设置为 5 分钟。检查：

```powershell
kubectl describe pod <pod-name> -n <namespace>
```

常见原因：

- ConfigMap 未创建或 `redis.conf` 路径不正确
- 镜像拉取慢（首次需要下载）
- 节点资源不足

## 4. Redis 连接失败

常见现象：

```text
failed to create Redis client for node <node>: could not connect to Redis
```

检查：

- Pod 是否 Running 且已分配 PodIP
- Service NodePort 是否正常工作
- 程序是否在能访问 NodePort 的节点上运行

处理建议：

- 程序通过 `127.0.0.1:<NodePort>` 连接 Redis，必须在 K8s 节点上运行
- 如果从集群外运行，需要能路由到节点的 NodePort

## 5. CLUSTER MEET 失败

常见现象：

```text
could not meet node <ip>: <error>
```

检查：

- 节点间网络互通（Pod 网络）
- Redis 容器是否正常启动（检查 `redis.conf` 内容和 `--port` 参数）
- 集群 bus 端口（redis_port + 10000）是否可达（Service 已暴露 bus 端口）

## 6. Slot 分配/迁移问题

如果 slot 分配后验证一直重试失败：

- 检查 master 数量是否正确
- 使用 `redis-cli -p <NodePort> CLUSTER NODES` 手动验证
- 检查 `AllocateSlots` 和 `VerifyAllocateSlots` 的日志输出

## 7. 集群扩容失败回滚

如果扩容中途失败：

- 新创建的 Pod 不会被自动清理（当前仅在创建流程有回滚）
- 需要手动 `cluster delete` 后重新 `cluster create`
- 或手动 `kubectl delete pod -l cluster-name=<name>` 清理残留 Pod

## 8. 运行时状态文件残留

如果手动删除了 K8s 资源但状态文件还在：

```powershell
# 手动清理
rm -r runtime/<clusterName>/
```

下次创建同名集群会自动覆盖旧文件。
