# 核心流程

## 1. 创建集群

入口：`cluster create`

核心流程如下：

1. `main.go` 已初始化配置，`cmd` 层将 `*RuntimeConfig` 和参数传入
2. `CreateClusterAction` 构建 K8s clientset 和 `K8sNodeManager`
3. 扫描 K8s 中已有 Pod（按 `managed-by=clusterManager` 标签）
4. 发现同名集群已存在时拒绝创建
5. `CreatePods` 并行创建 Redis Pod + NodePort Service + ConfigMap
6. 等待所有 Pod Running，获取 PodIP 和 NodePort
7. 选择一个节点作为登录节点，对其他节点执行 `CLUSTER MEET`
8. 拉取 `CLUSTER NODES` 信息，更新内存拓扑
9. 计算并设置主从关系（前 N 个为 master，其余为对应的 slave）
10. 给所有 master 分配 16384 个 slot
11. 写入运行时状态文件

### 创建时涉及的关键方法

- `CreateClusterAction` → `ClusterManager.CreateCluster`
- `K8sNodeManager.CreatePods` — 并行 Pod 创建 + 等待
- `ClusterManager.MeetNodes` — CLUSTER MEET 所有节点
- `ClusterManager.SetAllNodeRole` — 设置主从关系
- `ClusterManager.AllocateSlots` — 分配 16384 个 slot

### 主从分配方式

按 pods 顺序分配：前 N 个为 master，后 N×(nodesPerShard-1) 个为 slave。

### 回滚机制

如果创建中途失败，`defer` 会自动调用 `DeleteResources` 清理已创建的 Pod/Service/ConfigMap。

## 2. 删除集群

入口：`cluster delete`

流程：

1. 初始化配置和 K8s clientset
2. 删除运行时配置文件 (`run_time_config.yaml`)
3. 删除容器信息文件 (`containers.json`)
4. 调用 `K8sNodeManager.DeleteResources` 清理所有 K8s 资源（Service → Pod → ConfigMap，按标签选择）
5. 如果集群状态目录为空，删除之

## 3. 扩容集群

入口：`cluster scale`

流程：

1. 从 `run_time_config.yaml` 恢复集群配置（nodes-per-shard、port）
2. 构建 K8sNodeManager 和 ClusterManager
3. `ListPodsByCluster` 列出已有 Pod
4. `UpdateAfterMeet` / `UpdateAfterSetNodeRole` / `UpdateSlots` 恢复当前集群状态
5. `AddShards` — 创建新 Pod → MEET → 设置主从（新增节点当 empty master）
6. `MigratesSlotsToEmptyNode` — 从已有 master 迁移 slot 到新 master
7. `VerifyAllocateSlots` — 验证所有 master 持有正确的 slot 数量

### Slot 迁移流程

`MigrateSlot` 对一个 slot 执行：

1. 在目的节点执行 `CLUSTER SETSLOT <slot> IMPORTING <sourceID>`
2. 在源节点执行 `CLUSTER SETSLOT <slot> MIGRATING <destID>`
3. 获取 slot 中的 keys，批量 `MIGRATE`
4. 在目的和源节点执行 `CLUSTER SETSLOT <slot> NODE <destID>` 完成转移

## 4. Slot 分配算法

```text
slotsPerMaster = 16384 / numMasters
remainder = 16384 % numMasters
每个 master 分配 slotsPerMaster 个 slot
最后一个 master 额外分配 remainder 个 slot
```

例如 3 个 master：master[0]=0-5460, master[1]=5461-10921, master[2]=10922-16383
