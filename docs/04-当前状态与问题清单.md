# 当前状态与问题清单

## 1. 当前项目状态

项目已从 Podman 方案完全重写为 Kubernetes 原生方案（`feature/k8s-rewrite` 分支）。

已就绪：

- CLI 入口（create / delete / scale）
- K8s clientset 连接（kubeconfig / InClusterConfig）
- Pod / Service / ConfigMap 生命周期管理
- Redis Cluster 建群逻辑（CLUSTER MEET → 主从分配 → slot 分配 → 扩容迁移）
- 部分创建失败时的自动回滚
- 并行 Pod 创建（带 5 分钟超时）
- 配置通过 `*RuntimeConfig` 依赖注入（已消除全部包级全局变量）
- 单元测试（`cluster_node_test.go`、`config_unit_test.go`）+ 集成测试 build tag

## 4. 遗留风险与待改进项

### 4.1 测试覆盖不足

- 纯单元测试仅覆盖路径解析和 cluster node 行解析
- 核心编排逻辑（CreateCluster、SetAllNodeRole、AllocateSlots、MigrateSlot、AddShards）无单元测试
- 集成测试需要真实 K8s 集群，CI 中难以运行

### 4.2 Redis 连接通过 NodePort 回环

- 通过 `127.0.0.1:NodePort` 连接 Redis，要求程序在 K8s 节点上运行
- 如果程序在集群外运行，需要配置可路由的节点 IP

### 4.3 未使用 K8s Watch API

- Pod 就绪等待使用轮询 + sleep，效率低于 Watch

### 4.4 恢复已有集群的能力

- `LoadClusterPods` / `ListPodsByCluster` 可列出已有 Pod
- 但缺少将已有 Pod 状态恢复到 ClusterManager 中继续操作的完整流程

### 4.5 ClusterNode 冗余字段

- `PingSent`、`PongRecv`、`ConfigEpoch`、`AdditionalFlags` 被解析但未使用
- 不影响功能，但增加内存开销

## 5. 如果要继续维护，建议优先级

1. 为核心编排逻辑补单元测试（mock K8s clientset + Redis client）
2. 使用 K8s Watch API 替代轮询
3. 支持从已有 Pod 恢复集群状态
4. 补 CI pipeline（GitHub Actions）
5. 清理 ClusterNode 冗余字段
