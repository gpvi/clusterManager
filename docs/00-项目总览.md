# 项目总览

## 1. 项目是什么

`clusterManager` 是一个基于 Go 实现的 Redis Cluster 命令行管理工具，当前主要能力有三类：

- 创建集群
- 删除集群
- 扩容集群

项目通过 **Cobra** 提供 CLI，通过 **Podman API** 创建和管理 Redis 容器，通过 **go-redis** 调用 Redis Cluster 命令完成节点发现、主从配置和槽位分配/迁移。

## 2. 当前实现目标

从代码实现看，这个项目的目标不是做通用云平台，而是面向单机开发环境，自动完成以下事情：

1. 启动一批 Redis 容器
2. 让这些节点互相 `CLUSTER MEET`
3. 设置 master / replica 关系
4. 给 master 分配 16384 个 slot
5. 在扩容时新增节点并迁移 slot

## 3. 命令入口

程序入口是 [main.go](/e:/Projects/clusterManager/clusterManager-main/main.go)，实际命令定义在 `cmd/`：

- `cluster create`
- `cluster delete`
- `cluster scale`

示例：

```powershell
./cluster create -s 3 -r 2 -n demo -p 6379
./cluster scale -n demo -s 1
./cluster delete -n demo
```

## 4. 技术栈

- Go 1.23
- `github.com/spf13/cobra`
- `github.com/go-redis/redis/v8`
- `github.com/containers/podman/v5`
- YAML 配置 + JSON/YAML 运行时文件

## 5. 代码里的关键事实

结合当前源码，项目有几个很重要的实现事实：

- 现在命令层已经优先使用 `--shards` 和 `--nodes-per-shard`
- 为兼容旧脚本，`--shaderNum` 和 `--replica` 仍保留为废弃别名
- 创建成功后会落两个运行时文件：
  - `containers.json`：记录容器映射信息
  - `run_time_config.yaml`：记录副本参数和 Redis 端口
- 运行依赖 Podman socket，且当前代码中 Podman 连接地址写死为 macOS 用户目录

## 6. 当前最关键的问题

如果只抓最核心的回顾结论，当前项目主要卡在两点：

1. 跨平台能力不足
2. 关键配置没有完全提取出来

具体表现：

- Podman endpoint 写死在代码里，不能按 Windows / macOS / Linux 自动适配
- Redis 容器端口、Podman 连接地址等运行关键参数没有统一进入配置体系
- 当前默认实现更像“作者本机可运行的原型”，而不是“换台机器也能直接运行的工具”
