# 项目总览

## 1. 项目是什么

**Redis Data Platform**（仓库名 `clusterManager`）是一个基于 Go 实现的 Redis 集群全生命周期管理平台，支持 **四种运行模式**，覆盖 Redis 集群的创建、管理、缓存加速和自动化运维。

项目由 **Cobra CLI** 统一入口，底层通过多后端抽象（Kubernetes / Podman / Containerd）管理容器资源，通过 **go-redis** 执行 Redis Cluster 命令（节点发现、主从配置、槽位分配与迁移），并内置了分布式缓存子系统（GeeCache）。

---

## 2. 四种运行模式

### 2.1 CLI 工具（主模式）
默认运行模式，通过命令子集管理 Redis Cluster 生命周期：

| 命令 | 功能 |
|------|------|
| `cluster create` | 在 K8s/Podman/Containerd 上创建一批 Redis 节点，自动完成 `CLUSTER MEET`、主从配置、16384 个 slot 分配 |
| `cluster delete` | 删除指定集群 |
| `cluster scale` | 扩容：新增节点 + 从源 master 迁移部分 slot |
| `cluster cache` | 启动 Cache Node（见 2.2） |
| `cluster run` | 启动 gRPC Server（见 2.4） |

### 2.2 Cache Node（分布式缓存节点）
```
cluster cache --port=8001 --gossip=9001
```
启动一个 GeeCache 缓存节点，提供：

- **L1 内存缓存**：~1μs 响应，LRU + TTL 淘汰
- **一致性哈希**：key 分布到多节点
- **gRPC peer-to-peer 传输**：支持 TLS/mTLS
- **SWIM gossip（memberlist）**：节点自动发现与故障检测
- **热点 key 检测 & 复制**：自动识别高频 key 并冗余存储
- **Single-flight 请求合并**：并发重复请求合并为一次回源查询（go 库 `singleflight`）
- **DB 速率限制**：回源查询不超过阈值
- **RedisGetter bridge**：缓存未命中时 → Redis 集群查询 → 回填缓存
- **Slot 感知缓存失效**：收到 slot 迁移事件时自动失效相关缓存项

### 2.3 K8s Operator（CRD 驱动）
通过 Custom Resource Definition 驱动声明式 Reconciliation Loop。用户在 K8s 中创建 `RedisCluster` CR 对象，Operator 自动调谐至期望状态。

### 2.4 gRPC Server（clusterd）
```
cluster run
```
启动 gRPC 服务端（监听 `:50051`），暴露集群管理 API，适合作为控制面组件与其他系统集成。

## 3. 架构组件

### 3.1 多后端容器管理

| 后端 | 驱动 | 适用场景 |
|------|------|----------|
| **Kubernetes** | `client-go` | 生产环境 K8s 集群，管理 Pod / Service / ConfigMap |
| **Podman** | Podman API | 本地开发、单机测试 |
| **Containerd** | Containerd API | 轻量容器环境 |

三层抽象：`Backend` 接口 → 各后端实现 → `BackendManager`（运行时可切换，通过 `-b` 参数）。

### 3.2 缓存子系统（GeeCache）

独立于 Redis Cluster 管理的分布式缓存层，解决热点查询问题：

```
┌──────────────┐     gRPC      ┌──────────────┐
│  Cache Node  │◄────────────►│  Cache Node  │
│  (port 8001) │              │  (port 8002) │
└──────┬───────┘              └──────┬───────┘
       │                             │
       │  一致性哈希 路由              │
       ▼                             ▼
┌───────────────────────────────────────────┐
│              Redis Cluster                 │
│        （数据源，slot 分片）                 │
└───────────────────────────────────────────┘
```

- **缓存策略**：LRU + TTL
- **节点发现**：memberlist（SWIM gossip 协议）
- **热点检测**：计数器+阈值 → 自动复制热点 key 到多节点
- **请求合并**：singleflight 防止缓存雪崩
- **回源限流**：令牌桶保护后端 Redis
- **RedisGetter**：实现 `Getter` 接口，cache miss 时从 Redis 集群获取

### 3.3 DNS 节点发现

支持 DNS-based 节点发现，用于 Pod IP 动态变化场景：

- `DNSConfig` 结构体含命名模板（naming template）
- `ClusterMeetAddr()` 在 DNS 启用时返回主机名而非 IP
- `--cluster-announce-ip` 传递给 Redis 容器，确保客户端通过正确地址访问
- `GetNodeByHost()` 支持 hostname → IP 自动回退

### 3.4 SQLite 持久化

使用 SQLite 记录集群元数据，三张核心表：

| 表 | 内容 |
|----|------|
| `clusters` | 集群定义、后端类型、时间戳 |
| `containers` | 容器节点信息（含 hostname 列，自动 migration） |
| `operations` | 操作审计日志 |

支持 **auto-migration**：运行时会自动检查 schema，hostname 等新增列自动补充。

### 3.5 Python AI Agent（LLM 驱动运维）

位于 `ai-agent/` 目录，基于 **LangChain / LangGraph** 框架 + **GPT-4o**：

- 自然语言交互运维：_"给 cluster-a 加两个节点"_
- 自主规划 → 执行 → 验证
- 支持工具调用（Tool calling）：gRPC API、shell 命令
- 可观测的回溯日志（LangGraph 状态图）

## 4. 关键依赖

| 依赖 | 用途 |
|------|------|
| **Kubernetes client-go** | K8s Pod / Service / ConfigMap 生命周期 |
| **go-redis** | Redis Cluster 管理命令（MEET、REPLICATE、SETSLOT、ADDSLOTS 等） |
| **Cobra** | CLI 框架 |
| **YAML v2** | 配置文件解析 |
| **memberlist** | SWIM gossip 协议（缓存节点发现） |
| **gRPC** | 缓存节点间 P2P 传输 + clusterd 管理 API |
| **singleflight** | 请求合并，防止缓存惊群 |
| **modernc.org/sqlite** | 嵌入式 SQLite（纯 Go，无 CGO） |
| **LangChain / LangGraph** | AI Agent 框架（Python） |

## 5. 历史演进

- **v0** — 基于 Podman API 管理本地容器的 Redis 工具
- **v1** — `feature/k8s-rewrite` 完全重写为 Kubernetes 原生方案，消除全部包级全局变量（`RuntimeConfig` 依赖注入）
- **v2** — 扩展为多后端架构（K8s / Podman / Containerd），引入 SQLite 持久化
- **v3** — 新增分布式缓存子系统（GeeCache），支持一致性哈希、gossip 发现、热点复制
- **v4** — 新增 gRPC Server 和 CRD Operator 运行模式，新增 Python AI Agent
- **当前** — 项目从 CLI 工具演变为 **Redis Data Platform**，覆盖缓存、运维、自动化全链路

## 7. 快速上手

```bash
# 构建
go build -o clusterManager .

# 在 K8s 上创建 3master-3replica 集群
./clusterManager cluster create -n my-cluster -b k8s -m 3 -r 3

# 启动缓存节点（3 节点集群示例）
./clusterManager cluster cache --port=8001 --gossip=9001 --addrs=node1:8001,node2:8001,node3:8001

# 启动 gRPC Server
./clusterManager cluster run

# AI Agent 交互
cd ai-agent && python agent.py
```
