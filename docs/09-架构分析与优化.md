# 架构分析与优化方案

## 1. 当前架构全景

```
┌──────────────────────────────────────────────────────────────────┐
│                        用户入口                                   │

│              │      │         │      │ gRPC                       │
│              │      │         │      ▼                            │
│              │      │         │  clusterd:50051                   │
└──────┬───────┴──────┼─────────┴───────────────────────────────────┘
       │              │

┌──────────────────────────────────────────────────────────────────┐
```

### 四个二进制

| 二进制 | 入口 | 职责 |
|--------|------|------|
| `cluster` | `main.go` | CLI 工具（cobra 命令） |
| `cluster-operator` | `cmd/operator/main.go` | Controller，持续协调 CR |
| `clusterd` | `cmd/clusterd/main.go` | gRPC server，Agent 后端 |
| Python Agent | `agent/` | LangGraph 推理 + 编排 |

## 2. 问题清单

### 2.1 代码重复（P0）

**A. CreateCluster 逻辑三处重复**

| 位置 | 做了什么 |
|------|---------|
| `model/create_cluster.go:CreateClusterAction` | Pods → MEET → 主从 → slot → 保存状态文件 |
| `model/cluster_manager.go:CreateCluster` | Pods → MEET（不包含主从和slot） |
| `controller/:handleCreating` | Pods → MEET → 主从 → slot → 更新 Status |

三处实现相同的流程，但步骤略有不同。修复：将完整流程收敛到 ClusterManager 的一个方法中。

**B. NodeStatus 类型两处定义**

| 位置 | 结构体 |
|------|--------|
| `api/v1/rediscluster_types.go:NodeStatus` | CRD Status 的 Go 类型 |
| `proto/rediscluster.proto:NodeInfo` | gRPC 消息类型 |

两边编码相同的数据（id/ip/role/slots/healthy）。修复：Controller 统一使用 CRD 类型；clusterd 从 CR Status 读取，不需要单独的 proto 类型。

**C. Controller 健康检查中 nodeStatus 构建重复**

`handleCreating`、`handleReady`、`handleDegraded` 各自构建相同的 `NodeStatus` 切片（约70行重复）。修复：提取为 `buildNodeStatus` 函数。

### 2.2 缺失抽象（P1）

**A. 无接口，不可测**

```go
// 当前：所有消费者依赖具体类型
func (c *RedisClusterController) handleCreating(cr *v1.RedisCluster) error {
    nodeManager := model.NewK8sNodeManager(...)  // 具体类型，无法 mock
    clusterManager := model.NewClusterManager(...)
}

// 应有：
type NodeProvider interface {
    CreatePods(ctx context.Context, nodeNum int, clusterName string) error
    ListPodsByCluster(ctx context.Context, clusterName string) error
    DeleteResources(ctx context.Context, clusterName string) error
}
```

**B. RuntimeConfig 是可变结构体，不是接口**

被多处修改（`cmd/create.go` 覆盖 `RedisContainerPort`，controller 覆盖 `KubeNamespace`）。修复：改为不可变的值对象，通过 Builder 模式创建。

### 2.3 实现缺陷（P1）

**A. `CreateClusterWithProgress` 是假实现**

```go
// cmd/clusterd/main.go:85-112
time.Sleep(3 * time.Second)  // 硬编码等待，不是真实轮询
send("PodsCreating", 2, 4, "Operator creating pods")
time.Sleep(3 * time.Second)
send("Ready", 4, 4, "Cluster is ready")
```

应该轮询 CR Status 直到 Ready。

**B. 事件过滤错误**

```go
// cmd/clusterd/main.go:290
if evt.InvolvedObject.Name == name || evt.InvolvedObject.Name == "" {
    continue  // 空名字不应该跳过
}
```

**C. `ListPodsByCluster` 不重置 Nodes**

```go
// k8s_manager.go: ListPodsByCluster
c.Nodes = append(c.Nodes, &node)  // 追加，不重置 → 重复计数
```

### 2.4 配置流混乱（P2）

```
config/conf.yaml
  → Config.ReadConfig()
    → 环境变量覆盖
      → RuntimeConfig (全局变量在 cmd/ 中)
        → main.go 初始化
        → cobra 命令变异 cfg.RedisContainerPort
        → controller 创建自己的 InitConfig() 再覆盖 namespace
        → clusterd 创建自己的 InitConfig() 再覆盖 namespace
```

三个入口各自初始化配置，逻辑重复。修复：统一 `InitConfig()` 调用，只做一次，不可变传递。

### 2.5 错误处理不一致（P2）

| 组件 | 模式 | 问题 |
|------|------|------|
| Controller | `_ = c.updateStatus()` | 静默丢弃状态持久化错误 |
| clusterd | 混用 `status.Errorf` + `return nil, Success:false` | gRPC 调用方能分辨错误类型吗？ |
| CLI | `log.Printf("Error: %v", err)` | 未使用结构化日志 |
| model | `fmt.Errorf("xxx fail: %v", err)` | 无错误类型，无法程序化判断 |

### 2.6 未使用的定义（P3）

- `PhaseDeleting` 常量已定义，但 controller 没有对应的 handler
- `SlotMigrating` / `SlotUnbalanced` 常量已定义，但 controller 只写 `SlotBalanced`
- `ClusterNode.PingSent` / `PongRecv` / `ConfigEpoch` / `AdditionalFlags` 被解析但从未使用

## 3. 优化方案

### Phase 1: 消除重复 + 收敛流程（1周）

**1.1 提取接口**

```go
// model/interfaces.go (新文件)
type PodManager interface {
    CreatePods(ctx context.Context, nodeNum int, clusterName string) error
    ListPodsByCluster(ctx context.Context, clusterName string) error
    DeleteResources(ctx context.Context, clusterName string) error
}

type ClusterOrchestrator interface {
    Bootstrap(ctx context.Context, shardCount int, clusterName string) error
    HealthCheck(ctx context.Context, clusterName string) ([]NodeStatus, error)
}
```

让 `K8sNodeManager` 和 `ClusterManager` 实现这些接口。Controller 和 clusterd 依赖接口而非具体类型。

**1.2 收敛 CreateCluster 流程**

```go
// model/cluster_manager.go
func (c *ClusterManager) Bootstrap(ctx context.Context, shardCount int, clusterName string) error {
    // 完整的创建流程：Pods → 等待 Ready → MEET → 主从 → slot
    // CLI、Controller、clusterd 全部调用此方法
}
```

删除 `model/create_cluster.go:CreateClusterAction` 中的重复逻辑，改为调用 `Bootstrap` + 保存状态文件。

**1.3 提取 Controller 公共函数**

```go
// controller/helpers.go (新文件)
func buildNodeStatus(cm *model.ClusterManager, clusterName string) []v1.NodeStatus {
    // 从 ClusterManager 构建 NodeStatus 切片
    // handleCreating、handleReady、handleDegraded 共用
}
```

### Phase 2: 修复实现缺陷（1周）

**2.1 修复 `CreateClusterWithProgress`**

```go
func (s *clusterServer) CreateClusterWithProgress(req *pb.CreateClusterRequest, stream ...) error {
    // 1. 创建 CR
    // 2. 轮询 CR Status，每 2 秒推送进度
    for {
        cr, _ := s.dynamicClient.Resource(gvr).Get(ctx, name, metav1.GetOptions{})
        phase := getPhase(cr)
        stream.Send(&pb.CreateProgress{Phase: phase, ...})
        if phase == "Ready" || phase == "Degraded" {
            break
        }
        time.Sleep(2 * time.Second)
    }
}
```

**2.2 修复 `ListPodsByCluster` 重置问题**

```go
func (c *K8sNodeManager) ListPodsByCluster(ctx context.Context, clusterName string) error {
    c.Nodes = c.Nodes[:0]  // 重置
    // ... 重新填充
}
```

**2.3 修复事件过滤**

删除 `|| evt.InvolvedObject.Name == ""` 条件，通过标签选择器过滤事件。

### Phase 3: 配置流统一（3天）

**3.1 不可变 RuntimeConfig**

```go
// RuntimeConfig 字段全部改为私有，通过构造函数创建
func NewRuntimeConfig(yamlPath string) (*RuntimeConfig, error) { ... }

// 派生配置（覆盖特定字段）返回新实例
func (c *RuntimeConfig) WithNamespace(ns string) *RuntimeConfig { ... }
func (c *RuntimeConfig) WithPort(port uint16) *RuntimeConfig { ... }
```

**3.2 统一入口初始化**

```go
// main.go / cmd/operator/main.go / cmd/clusterd/main.go 都调用同一个函数
cfg, err := model.NewRuntimeConfig("config/conf.yaml")
```

### Phase 4: 错误处理标准化（2天）

**4.1 定义错误类型**

```go
// model/errors.go
var (
    ErrClusterNotFound   = errors.New("cluster not found")
    ErrClusterExists     = errors.New("cluster already exists")
    ErrPodsNotReady      = errors.New("pods not ready")
)
```

**4.2 Controller 不吞错误**

```go
if err := c.updateStatus(ctx, cr); err != nil {
    log.Printf("failed to update status for %s: %v", cr.Name, err)
    return err  // 触发重试
}
```

### Phase 5: 删除死代码（1天）

- 删除 `PhaseDeleting`（如不计划实现）
- 删除 `SlotMigrating`/`SlotUnbalanced`（如不计划实现）
- 删除 ClusterNode 中未使用的字段

## 4. 优化后的目标架构

```
┌─────────────────────────────────────────────────────────────┐
│  入口层 (只做参数解析 + 调用共享层)                            │
│  CLI / gRPC clusterd / Python Agent / Operator              │
└────────────────────────┬────────────────────────────────────┘
                         │ 依赖接口
┌────────────────────────▼────────────────────────────────────┐
│  model/interfaces.go   PodManager, ClusterOrchestrator       │
├─────────────────────────────────────────────────────────────┤
│  model/ (共享实现)                                           │
│  ├── config.go       RuntimeConfig (不可变)                  │
│  ├── k8s_client.go   NewK8sClientset                        │
│  ├── k8s_manager.go  PodManager 实现                        │
│  ├── cluster_manager.go  ClusterOrchestrator 实现            │
│  │   ├── Bootstrap()   统一创建流程                          │
│  │   ├── HealthCheck() 统一健康检查                          │
│  │   ├── Scale()       统一扩容流程                          │
│  │   └── Delete()      统一删除流程                          │
│  ├── errors.go       结构化错误                              │
│  └── cluster_node.go  ClusterNode 类型                      │
├─────────────────────────────────────────────────────────────┤
│  api/v1/         CRD 类型（唯一的 NodeStatus 定义）          │
│  proto/          gRPC 契约（引用 api/v1 类型）               │
│  controller/     Operator 协调循环                            │
└─────────────────────────────────────────────────────────────┘
```

## 5. 收益总结

| 维度 | 当前 | 优化后 |
|------|------|--------|
| CreateCluster 实现 | 3 处重复 | 1 处 (Bootstrap) |
| NodeStatus 定义 | 2 处 (CRD + proto) | 1 处 (CRD) |
| 可测试性 | 依赖具体类型 | 依赖接口，可 mock |
| Config 突变点 | 4 处 | 0（不可变） |
| 错误处理 | 3 种不一致模式 | 统一结构化错误 |
| ListPodsByCluster | 重复计数 bug | 正确重置 |
| CreateClusterWithProgress | 假实现 (sleep) | 真轮询 CR Status |
| 死代码 | ~5 个未使用常量/字段 | 0 |
