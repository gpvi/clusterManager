# 开发与测试指南

## 1. 开发环境

推荐环境：

- Go 1.23 或兼容版本
- Podman CLI
- Podman machine 或本机 Podman service
- PowerShell，用于运行仓库内脚本

项目依赖 Podman v5 Go bindings。构建和测试时推荐加上 `containers_image_openpgp` tag，以绕开对本机 `gpgme` 的额外依赖。

## 2. 构建

推荐：

```powershell
./scripts/build.ps1
```

等价命令：

```powershell
go build -tags containers_image_openpgp -o cluster .
```

`scripts/build.ps1` 会在仓库内创建 `.gocache`，并把 `GOCACHE` 指向该目录，避免污染用户全局缓存。

## 3. 默认测试

推荐：

```powershell
./scripts/test.ps1
```

等价命令：

```powershell
go test -tags containers_image_openpgp ./...
```

脚本会额外准备：

- `.gocache`
- `.testcontainers/containers.conf`
- `CONTAINERS_CONF` 环境变量

这些设置主要是为了让 Podman 相关依赖在 Windows 本地测试时更稳定。

## 4. 集成测试

真实 Podman / Redis Cluster 集成测试需要显式开启：

```powershell
$env:CLUSTER_RUN_INTEGRATION_TESTS="1"
go test -tags "integration containers_image_openpgp" ./model -v
```

集成测试会依赖真实 Podman 环境，运行前请确认：

- Podman machine 已启动
- Redis 镜像 `myredis` 已构建
- `config/conf.yaml` 或环境变量中的路径对 Podman service 可见
- 测试结束后确认残留容器已清理

## 5. 镜像构建

默认镜像名来自 `config/conf.yaml`：

```yaml
configs:
  image_name: "myredis"
```

构建命令：

```bash
./scripts/build-image.sh
```

等价命令：

```bash
podman build -t myredis -f ./setup/redisv3.dockerfile .
```

## 6. 代码分层约定

当前项目的边界大致如下：

- `cmd/`：只处理命令、参数和用户入口
- `model/config.go`：读取配置并设置运行期参数
- `model/containers_manager.go`：封装 Podman 容器创建、扫描、删除所需信息
- `model/cluster_manager.go`：封装 Redis Cluster 拓扑、角色、slot 操作
- `model/create_cluster.go`、`scale_cluster.go`、`delete_cluster.go`：动作级编排
- `utils/`：无业务状态的通用工具

新增功能时，优先保持这个分层。比如新增 `status` 命令时，建议 `cmd/status.go` 只负责参数解析，实际读取容器和 Redis Cluster 状态的逻辑放在 `model/`。

## 7. 配置开发注意事项

当前配置最终会落到一组全局变量，例如：

- `RedisHostConfigPath`
- `RuntimeStateDir`
- `PodmanEndpoint`
- `PodmanNetworkName`
- `RedisContainerPort`

这让现有代码调用简单，但也让测试隔离更困难。写新测试时要注意：

- 修改全局配置后恢复原值
- 不要让测试互相依赖执行顺序
- 集成测试使用独立集群名

## 8. 运行态产物

本地运行会生成：

```text
.gocache/
.testcontainers/
runtime/
cluster
```

这些都属于构建或运行产物，不应提交到 Git。

## 9. 建议的提交前检查

```powershell
./scripts/test.ps1
./scripts/build.ps1
```

如果改动涉及 Podman 连接、容器创建、集群扩容或删除，再额外跑一次集成测试。
